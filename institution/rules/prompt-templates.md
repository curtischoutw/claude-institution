# 任務交辦 prompt 範本

<!-- 按需引用檔。交辦 subagent 時抄對應範本填空，不要即興寫。
     模型選擇見 dispatch.md 調度表。建立：2026-07-05（Fable 5 session）。 -->

通用鐵則（每份 prompt 都要包含最後兩行）：
- 「查不到／做不到就直說，禁止編造。」
- 「回報上限 N 行；長產物存到 <路徑> 後只回路徑＋3 行摘要。」

## 1. 搜尋（Explore + haiku）

```
在 <repo 路徑> 找出 <目標：例如「所有呼叫 get_user() 的位置」>。
動機：<為什麼要找，讓它能判斷邊界案例算不算>。
範圍：<目錄/檔案類型>；也要檢查 <別名/舊名/字串引用等變形>。
驗收條件：回報涵蓋 <明確涵蓋判準，例如「含測試檔與設定檔」>。
回報格式：每筆一行「檔案:行號 — 一句話說明用途」；最後一行寫總數。
找不到就回「無結果」並列出你搜過的 pattern。禁止編造。回報上限 30 行。
```

## 2. 實作（general-purpose + sonnet）

```
目標與動機：實作 <功能>，因為 <動機>。
規格：<輸入/輸出/行為，逐條>。
限制：只准動 <檔案範圍>；遵守 ~/.claude/rules/hard-rules.md 與 code-standards.md；
不確定的設計決策先用最簡單解並在回報標註 ASSUMPTION。
驗收條件：<指令> 執行結果為 <預期>；新增測試 <名稱> 且全綠。
回報格式：改動清單（檔案:行號＋一句話）、實跑輸出尾 10 行、ASSUMPTION 清單。上限 40 行。
做不到就停下回報卡點，禁止交出沒跑過的程式碼。
```

## 3. 重構（general-purpose + sonnet）

```
目標與動機：把 <對象> 重構為 <目標形態>，因為 <動機>。
不變式（絕不能變的行為）：<列出，例如「所有現有測試不改內容且全綠」「公開 API 簽名不變」>。
步驟：先跑 <測試指令> 記錄基線 → 小步重構 → 每步重跑測試。
驗收條件：測試基線與終點輸出一致全綠；diff 中無行為變更（只有結構變更）。
回報格式：基線輸出尾 5 行、終點輸出尾 5 行、改動摘要（檔案:行號）。上限 30 行。
任何一步測試變紅且 2 次內修不回 → 立即 revert 全部並回報，不要硬推。
```

## 4. 研究（general-purpose + haiku；需要權衡結論時用 sonnet）

```
問題：<要回答的具體問題>。
動機：<這答案會用來做什麼決定>。
來源優先序：<官方文件 > 原始碼 > 其他>；每個結論附出處（URL 或 檔案:行號）。
驗收條件：問題的每個子項都有「已確認＋出處」或「查不到」；區分事實與你的推測。
產物：完整筆記存到 <路徑>。
回報格式：結論 ≤10 行＋產物路徑。禁止用訓練記憶充當查證結果。
```

## 5. 審查（general-purpose + opus；fresh context，不給實作者自述）

```
審查對象：<路徑或 diff>。規格：<原始需求，逐條>。
你是沒有參與實作的審查者，只依規格與程式碼本身判斷。
檢查清單：規格每條是否達成（逐條勾）、有無弱化測試、有無除錯碼、
有無規格外的多餘改動、<領域特定風險，例如並發/安全>。
可實跑：<測試/啟動指令>，貼輸出。
回報格式：verdict（通過/退回）＋問題清單（檔案:行號＋嚴重度＋一句話修法），
按嚴重度排序。上限 30 行。沒把握的問題標「不確定」，不要憑印象斷言。
```
