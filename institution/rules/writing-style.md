# 寫進檔案、文件、簡報、網頁的文字

- 用描述，不用比喻。講「不會報錯、只在特定日期失敗」，不要講「沉默的地雷」。
  唯一例外：解釋抽象概念時比喻比直述好懂（k-core 的「一層一層剝掉」），
  且該比喻本身不帶價值判斷。
- 不用誇飾動詞代替現象：爆量、卡爆、炸掉、瞬殺 → 寫實際發生什麼
  （運算量從 O(n) 變成 O(n²)、記憶體超出 8 GB、10 秒內無法完成）。
- 不用「順手」「小改一下」「簡單處理」淡化工作量，也不用「大幅」「徹底」「完美」放大。
  能給數字就給數字。
- 同一句、同一段裡不要為了避免重複而換同義詞（位置／座位、變數／欄位）。
  技術文件的一致性優先於文字變化。
- 已經用直述講完的事，不要再補一個比喻收尾。
- 絕對化的斷言（唯一、全部、永遠、必定）要能在同一份文件裡自圓其說；
  不確定就寫「少數之一」「多數情況」。
- 寫完檢查：每個形容詞刪掉之後句子是不是還成立。成立就刪掉。
