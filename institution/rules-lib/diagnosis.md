# 快速診斷：本 harness 三大耗損源

<!-- 按需引用檔。本檔只留排名、症狀與獨有規則；修法細節住在對應規則檔，不重述。 -->

## 第 1 名：主對話下場幹粗活（最漏 token）

症狀：主對話連續 Read 多檔、Grep 大範圍、貼長指令輸出——每筆永久佔據主 context，
後續每次推理重複計費，並稀釋注意力（失焦的主因也是它）。
修法 → hard-rules #11（觸發條件）與 `dispatch.md`（派法、模型、回報合約）。

## 第 2 名：常載檔膨脹與規則只加不刪（最易失焦）

症狀：常載檔越長，單條規則服從率越低；規則互相矛盾時弱模型會隨機挑一條（推測性
斷言，未實測，但方向有普遍共識）。每個 session 都重複燒這些 token。
修法 → `maintenance.md` 精簡門檻表。
獨有規則：想加一條常載規則之前，必答兩題——(1) 能不能做成 hook（機器強制）？
(2) 能不能放進按需引用檔或 skill（用時才載入）？兩題都答「不能」才准進常載檔。

## 第 3 名：自驗自查與假完成（最易出錯）

症狀：同一個 context 裡「寫的人」兼「驗的人」，驗證淪為確認偏誤；「✅ 測試通過」
卻沒貼輸出是最典型的假完成。
修法 → `/done-check` skill 與 `dispatch.md`「驗證（不自驗）」節。
