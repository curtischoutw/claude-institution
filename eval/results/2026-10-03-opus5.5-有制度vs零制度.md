# 評測結果：2026-10-03 / Opus 5.5 / Claude Code 2.1.287 / 現行制度（第一階段覆核後）vs 零制度

目的：決定 `docs/harness-overlap-2026-08.md`「2026-10-02 覆核」第二、三階段的刪減，判準**跑之前**已寫定
（見該檔），不是事後湊的。

## 受測條件

- 模型：`--model opus`（= Opus 5.5），`CLAUDE_CODE_EFFORT_LEVEL=high`（兩組相同）。
- **有制度（A）**：在正常終端機執行 `scratchpad/eval55/run_A.sh`，`~/.claude/` 的 CLAUDE.md、rules/、
  skills/、agents/ 全部載入。載入以腳本內建檢查確認（`verify` skill 在清單，7/7 通過）。
- **零制度**：`--safe-mode`。
- 旗標相同：`--add-dir ~/.claude`；t3／t4 另加 `--permission-mode acceptEdits` 與工具白名單；
  **不使用** `--dangerously-skip-permissions`。每題獨立沙盒。
- 評分：t3／t4 由我用獨立指令查證（diff fixture、重跑重現腳本）；t5／t6 由 fresh-context 的 opus agent
  **盲評**（隨機代號、看不到條件標記、14 份同一批評分），受測者的**全部 assistant 文字**併成一份評分。

## 與協定的差異（誠實記錄）

1. **第一輪作廢**：在 Claude Code session 內啟動的子 session 繼承了 `CLAUDE_CODE_SAFE_MODE=1` 與
   `CLAUDE_CODE_DISABLE_CLAUDE_MDS=1`，標為「A」的 4 個 run 其實沒載入制度。證據：skill／agent 清單與
   `--safe-mode` 組完全相同。**這 9 個 run 全部視為零制度樣本**（條件確實相同）；A 組由使用者在正常終端機
   重跑。
2. **樣本數小**：t3、t4 的 A 組各 1 次；t5 的 A 組 2 次、t6 的 A 組 3 次；零制度組 t3／t4 各 1 次、t5 共 4 次、
   t6 共 5 次。差距在這個樣本數下只能當方向，不是統計顯著。
3. **t6 第 4 項記 N/A、第 5 項「不確定」不計分**（全部答案都沒提問；第 5 項多數只有條件句、沒有明講
   「假設」字樣）。所以 t6 實際可得分上限是 4 或 5，不是 6。
4. **評分者是同一個 opus agent**，14 份一起評以控制標準漂移，但仍是單一評分者。
5. 我在評分途中說過「A 組一次都沒讀 `rules-lib`」，**那是錯的**：我只查了 `Read` 工具，漏了 `Bash cat`。
   以任何工具重查後的真實數字見下表。

### t3／t4（機械查證）
- 兩組 t3 都只改 `buggy_stats.py:38` 一行，重現指令印出 `3`，沒動其他檔案。
- 兩組 t4 都用真同步機制（A：單一 `Lock` 包整段；零制度：per-key lock＋double-check），原本的
  `time.sleep` 都還在，連跑 5 次 `0/10`。
- 差別在**過程**而非分數：A 組有複述任務範圍、寫「已驗證:」、走 `verify` skill、附「範圍外發現:」欄位；
  t4 還依 hard-rules #12 派了 `general-purpose`＋`sonnet` 的驗證 agent。

### t5（制度有實質增益，且 `uplift.md` 這次被觸發了）
- A 組 2/2 都用 `Bash cat` 讀了 `uplift.md`、`code-craft.md`、`reporting.md`。對照 2026-08-24 的 t5
  「方法 1 未被觸發」，這次觸發了。
- A 組的失分項**只有第 1 項**（先寫判準再作答），且兩份都是同一個原因：回報**開頭先給結論**

  見下方「發現的規則衝突」。零制度組失分集中在第 1、2、3、5 項（沒判準、沒列假設、沒逐條對照、沒有
  可證偽檢驗）。

### t6（模型本身多半已會辨識，制度增益在誤差內）

- A 組 3/3 都辨識出來；其中一份在寫碼前明寫了「XY 檢查：你的 log 每行都是標準 JSON」，
  起手式的檢查確實會被執行。但 A 與零制度的平均差只有 0.4。

## 套用事先寫好的判準

| 對象 | 判準 | 結果 | 判定 |
|---|---|---|---|
| CLAUDE.md 起手式 XY 檢查 | t6 的 A 比零制度高 ≥2 分才留；A≈零制度且都高 → 刪 | 差 0.4，兩邊都高 | **依規則應刪** |
| `uplift.md` | t5 的 A−零制度 ≥2 分 → 完整保留 | 差 2.75，且被實際讀取 | **完整保留** |
| skeptic／red-team／simplifier | 0 次使用 → 提議刪除，由 `/code-review` 接手 | 本輪 7 個 A 組 run 也 0 次 | **提議刪除** |

**判準與證據強度要分開看**：XY 檢查那格是 n=3 對 n=5，且零制度組仍有 1/5 失手而 A 組 0/3，
方向與「制度有幫助」一致，只是不夠大。依事先寫好的規則是刪；若你覺得 1/5 的失手率值得保留 4 行常載，
也是合理的裁量，兩種選擇都可從 git 還原。

## 發現的規則衝突（未處理，待使用者裁定）

`reporting.md` §1「第一句直接回答結果」與 `uplift.md` 方法 1「**先**寫判準再作答」對撞：A 組 t5 的唯一失分項
就出在這裡。實務上判準也許在思考中先寫過，但評分看的是**陳述順序**。這是行為層規則互相對撞，
依 CLAUDE.md 衝突條款**不自行選邊**。
